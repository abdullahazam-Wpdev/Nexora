## Explicitly not done this pass, and why

- **Phase E (REA research into published architecture papers)**: this
  needs real reading and synthesis across OpenAI/Anthropic/DeepSeek/
  NVIDIA/Qwen/Kimi published material, which is itself a multi-hour
  research task distinct from the training/evaluation work above; doing it
  shallowly (a few search snippets passed off as "research") would not
  meet this project's own bar for evidence-based claims.
- **Phase H (installing a larger reference model)**: the measured ~1 GiB
  available RAM (`docs/phase5-system-audit.md`) means a materially larger
  Ollama/LocalAI model is a real risk to this already swap-heavy machine;
  this needs your explicit approval before a multi-GB download/load, per
  the project's own resource-management rule, and no such approval was
  given this pass.
- **Phase I (coworker workflow: plan → tool selection → approval →
  execution → verification)**: the existing coworker already implements
  explicit user-directed actions (`/write`/`/read`/`/run`); building the
  described approval/planning loop on top is a real feature addition, not
  a quick patch, and risking it on NEXORA's own repository without first
  testing on a disposable project (as the prompt itself requires) needs
  dedicated time this pass didn't have left after the training/evaluation
  work above.
- **Phase J (continuous learning supervisor)**: this is a new subsystem
  (proposal generation, approval gating, regression rejection) that
  deserves its own design pass, not a bolt-on; `docs/INSTRUCTION_TUNING.md`
  and `docs/NEXORA_CORE_TRAINING.md` already establish the manual version
  of its promotion gate (evaluate, compare, do not auto-promote) that any
  future automation would need to encode faithfully.
- **Phase K (UI changes)**: the live chat/provider/health behavior was
  verified through the real API this pass; the browser frontend itself
  was not opened or changed, since nothing in this pass's findings
  required a UI change (no new user-facing provider needed exposing
  beyond what the existing provider list already renders).
